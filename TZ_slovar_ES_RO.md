# Техническое задание
## Мобильно-веб приложение «Словарь»: испанско-румынский / румынско-испанский

**Версия:** 1.0
**Дата:** 26.09.2026
**Назначение документа:** ТЗ для разработки с помощью Claude Code, с последующим деплоем на бесплатном хостинге (GitHub Pages / GitHub Actions + бесплатный backend-хостинг).

---

## 1. Цель проекта

Разработать веб-приложение (с возможностью в будущем обернуть в мобильное) — двуязычный словарь испанский↔румынский с распознаванием слов по фото, переводом со значением, интерактивными квизами и AI-чат-ботом для практики языка. Дизайн — минималистичный, светлый, в стиле Lingvanex/Linguee/Duolingo-лайт, с переключением на тёмную тему.

## 2. Целевая аудитория

Пользователь, изучающий испанский и/или румынский язык (в т.ч. сам автор проекта), которому нужен быстрый способ узнать слово (в т.ч. с фото), проверить его перевод/значение и закрепить материал через практику.

## 3. Ключевые предположения и допущения (уточнить при необходимости)

Так как в исходном запросе не были явно определены некоторые технические детали, ниже приведены рабочие допущения — их можно поменять до начала разработки:

- «Бесплатный сервер от Git» интерпретируется как: **GitHub** в качестве репозитория + CI/CD (GitHub Actions), **GitHub Pages** — для статического фронтенда, и один из бесплатных backend/БД-хостингов (Render / Fly.io / Railway free tier / Supabase / Neon) — для API и базы данных, так как чистый GitHub Pages не умеет исполнять серверный код.
- Приложение — веб-приложение (PWA), адаптивное под мобильный экран, без нативной публикации в App Store/Google Play на первом этапе.
- Пары языков фиксированы: испанский ↔ румынский (без промежуточного английского в интерфейсе).

## 4. Функциональные требования

### 4.1 Распознавание слова по фотографии
- Пользователь загружает фото (или делает снимок с камеры телефона/веб-камеры).
- Приложение распознаёт текст на изображении (OCR) и выделяет отдельные слова, доступные для выбора.
- Пользователь нажимает на нужное слово → приложение показывает перевод и значение (см. 4.2).
- Технически: OCR через готовый API/библиотеку (например, Tesseract.js — бесплатно и офлайн, либо облачный OCR API с бесплатным лимитом — Google Cloud Vision / OCR.space).

### 4.2 Перевод и значение слова
- Пользователь вводит слово (или выбирает распознанное с фото) на испанском или румынском.
- Приложение автоматически определяет язык исходного слова.
- Результат:
  - Перевод слова на второй язык.
  - Значение (толкование) слова, прописанное **на румынском языке** (по условию ТЗ — значение всегда даётся на румынском, независимо от того, испанское это слово или румынское).
  - При наличии — часть речи, род (для румынского/испанского существительных), примеры употребления.
- Источник данных: комбинация словарного API/базы + верификация (см. 4.4).

### 4.3 Ручное добавление слов
- Пользователь может вручную добавить новое слово в свой личный словарь: слово, язык, перевод, значение (пример — опционально).
- Добавленные вручную слова помечаются как «пользовательские» и участвуют в квизах наравне с остальными.
- Возможность редактировать/удалять свои слова.

### 4.4 Верификация корректности слов
- Слова, добавляемые в базу (автоматически через переводчик или вручную пользователем), должны быть проверяемы одним из двух способов:
  1. **AI-проверка** — запрос к LLM (тому же движку, что использует чат-бот) с просьбой подтвердить корректность перевода/значения.
  2. **Проверка через внешние словарные сайты** — сверка с авторитетными онлайн-словарями:
     - для румынского — DEX online (dexonline.ro);
     - для испанского — RAE (rae.es) или Wiktionary.
- Приложение обязательно работает при наличии интернет-соединения (в отличие от чисто офлайн-словаря) — это заложено в архитектуру как требование.
- Слова, не прошедшие верификацию, помечаются как «непроверено» и не участвуют в квизах, либо показываются с предупреждением.

### 4.5 Интерактивные квизы
Набор форматов (реализовать минимум 4 на MVP, остальные — по возможности):
- **Вставь слово в предложение** — пропуск в предложении, нужно выбрать/вписать правильное слово.
- **Подбери перевод** — выбор правильного перевода из нескольких вариантов (multiple choice).
- **Флеш-карты (flashcards)** — карточка «слово → перевод/значение» с переворотом, режим самопроверки (знаю / не знаю).
- **Сопоставление (matching)** — соединить пары «слово — перевод» из списка.
- **Правописание / ввод с клавиатуры** — услышать/увидеть перевод, ввести слово на языке оригинала.
- Прогресс и статистика по каждому режиму сохраняются (сколько слов выучено, процент правильных ответов, слова «на повторении» по интервальному повторению — spaced repetition, как в Anki).

### 4.6 Чат-бот для практики диалога
- Отдельный экран «Диалог с ботом»: пользователь может вести переписку на испанском или румынском с AI-ботом.
- Бот поддерживает простой разговор на выбранную тему (бытовые ситуации, путешествия, покупки и т.п.), мягко поправляет ошибки, может пояснить слово/грамматику по запросу.
- Реализация — через LLM API (Claude API/иной, с бесплатным или недорогим лимитом; либо самостоятельный бесплатный лимит через прокси-сервис).
- (Опционально, если останется время) — голосовой ввод/озвучка ответов (Web Speech API, бесплатно в браузере).

### 4.7 Дополнительные функции (желательно, не обязательно на MVP)
- Избранное / закладки для слов.
- История поиска.
- Ежедневное «слово дня».
- Push/локальные напоминания о практике (для PWA).
- Экспорт личного словаря (CSV/JSON).

## 5. Нефункциональные требования

### 5.1 Дизайн
- Минималистичный стиль, референс — Lingvanex/Linguee: много белого пространства, чистая типографика, акцентный цвет — один (например, синий или зелёный), без визуального шума.
- Светлая тема — основная (белый фон), с переключателем на тёмную тему (кнопка/иконка в шапке, сохраняется в настройках пользователя — localStorage).
- **Mobile-first подход**: вёрстка проектируется в первую очередь под телефон (320–430px ширины), десктоп — как расширение той же сетки, а не отдельный дизайн.
- Простая, понятная навигация: 4–5 основных разделов, на мобильном — нижняя таб-бар навигация (Словарь / Поиск+Фото / Квизы / Чат-бот / Профиль), привычная для приложений, а не «гамбургер»-меню.

### 5.2 Требования к мобильному опыту (приоритет)
- **PWA (Progressive Web App)**: manifest.json + service worker, чтобы приложение можно было «установить» на экран телефона (Android/iOS) и запускать как обычное приложение, без магазина.
- **Touch-friendly интерфейс**: все интерактивные элементы (кнопки, карточки квизов, элементы флеш-карт) — минимум 44×44px для удобного нажатия пальцем; достаточные отступы между элементами, чтобы избежать случайных нажатий.
- **Жесты**: поддержка свайпов там, где это естественно — переворот флеш-карты по тапу, свайп «знаю / не знаю» в режиме флеш-карт, свайп между карточками.
- **Камера**: кнопка «сфотографировать слово» должна сразу открывать камеру телефона (`<input type="file" accept="image/*" capture="environment">` или доступ через `getUserMedia`), а не только загрузку файла из галереи.
- **Виртуальная клавиатура**: поля ввода не должны перекрываться клавиатурой телефона; для полей поиска — атрибут `inputmode` и авто-фокус без резких прыжков вёрстки.
- **Safe area / вырезы экрана**: учитывать отступы под «чёлку»/индикатор жестов на iPhone (`env(safe-area-inset-*)` в CSS), особенно для нижней таб-бар навигации.
- **Ориентация и viewport**: корректный `<meta name="viewport">`, без горизонтального скролла, работа как в портретной, так и (по возможности) в альбомной ориентации.
- **Работа на мобильном интернете**: оптимизация под нестабильную/медленную связь (3G/слабый Wi-Fi) — сжатие запросов к API, индикаторы загрузки, повторные попытки при обрыве соединения, компрессия загружаемых фото перед отправкой на OCR.
- **Тестирование**: обязательная проверка на реальных мобильных браузерах (Chrome Android, Safari iOS) перед каждым релизом, а не только в desktop dev-tools эмуляторе.

### 5.3 Производительность и доступность
- Работа только при наличии интернета — это заложено в требованиях (пункт 4.4), офлайн-режим не обязателен (кроме базового офлайн-экрана PWA с сообщением «нет соединения»).
- Время отклика на перевод/поиск — в пределах 1–3 секунд на Wi-Fi, приемлемая деградация на мобильной сети.
- Поддержка современных браузеров, в первую очередь мобильных (Chrome Android, Safari iOS), затем — десктопных (Chrome, Firefox).

### 5.4 Хранение данных
- Личный словарь пользователя, прогресс по квизам, настройки темы — хранятся в базе данных на backend (не только в localStorage), чтобы не терять данные при смене устройства.
- Необходима простая система аккаунтов (email/пароль либо OAuth через Google) — либо, на первом этапе, анонимный локальный профиль с возможностью привязки аккаунта позже.

## 6. Архитектура и технологический стек (рекомендация)

| Слой | Технология | Обоснование |
|---|---|---|
| Frontend | React (Vite) или Next.js (static export) | Простой деплой на GitHub Pages / Vercel free tier, много готовых компонентов |
| Стили | Tailwind CSS | Быстро реализовать минималистичный дизайн + тёмную тему через `dark:` классы |
| Backend / API | Node.js + Express (или serverless-функции на Vercel/Render) | Бесплатный тир на Render/Railway; легко писать эндпоинты для перевода, верификации, квизов |
| База данных | PostgreSQL на Supabase или Neon (бесплатный тир) | Бесплатно, готовая аутентификация (Supabase Auth) «из коробки» |
| OCR (фото → текст) | Tesseract.js (клиентский, бесплатный) или Google Cloud Vision (бесплатный лимит) | Не требует своего сервера для базового распознавания |
| Перевод / словарные данные | LibreTranslate (self-hosted, бесплатно) или DeepL API free tier, + Wiktionary/DEX online для сверки | Комбинация даёт и перевод, и способ верификации |
| AI-верификация / чат-бот | Claude API (или иной LLM API с бесплатным лимитом) | Один и тот же провайдер для верификации слов и диалогового бота |
| Хостинг фронтенда | GitHub Pages / Vercel (free) | Бесплатно, деплой через GitHub Actions при пуше в main |
| Хостинг backend | Render / Railway free tier | Поддерживает Node.js, деплой из GitHub-репозитория |
| CI/CD | GitHub Actions | Автосборка и деплой при каждом пуше |

> Примечание для Claude Code: при инициализации проекта уточнить у пользователя лимиты выбранных бесплатных сервисов (Render/Supabase могут «усыплять» backend при неактивности — учитывать в UX, например показ спиннера «сервер просыпается»).

## 7. Модель данных (упрощённо)

- **User**: id, email (опционально), настройки (тема), дата регистрации.
- **Word**: id, text, язык (es/ro), перевод, значение (на румынском), часть речи, статус верификации (verified / unverified / ai-verified / source-verified), источник, дата добавления, is_custom (добавлено вручную), owner_id (если личное).
- **QuizProgress**: id, user_id, word_id, тип квиза, количество попыток, процент успеха, дата следующего повторения (для spaced repetition).
- **ChatSession** (опционально для MVP): id, user_id, язык, история сообщений.

## 8. Основные экраны (UX-flow)

1. **Главная / Поиск** — поле ввода слова + кнопка «сфотографировать/загрузить фото» → результат перевода и значения.
2. **Экран результата слова** — перевод, значение (на румынском), часть речи, статус верификации, кнопка «Добавить в мой словарь».
3. **Мой словарь** — список добавленных слов (свои + сохранённые), фильтр по языку/статусу, поиск, редактирование.
4. **Квизы** — выбор режима (вставь слово / перевод / флеш-карты / сопоставление / ввод), экран прохождения, экран результатов.
5. **Чат-бот** — окно диалога, выбор языка практики, история сообщений.
6. **Профиль/Настройки** — статистика прогресса, переключатель темы, аккаунт.

## 9. Этапы разработки (предложенный roadmap для MVP)

**Этап 1 — Каркас**
Настройка репозитория, CI/CD, базового фронтенда (роутинг, светлая/тёмная тема), пустой backend с health-check эндпоинтом.

**Этап 2 — Поиск и перевод слова**
Реализовать ручной ввод слова → перевод + значение через API, сохранение в БД, статус верификации через словарные источники.

**Этап 3 — Распознавание по фото**
Интеграция OCR (Tesseract.js) → выбор слова из распознанного текста → передача в модуль перевода (Этап 2).

**Этап 4 — Личный словарь**
CRUD для ручного добавления слов, привязка к пользователю/сессии.

**Этап 5 — Квизы**
Реализовать минимум 3–4 формата квизов на основе слов из личного словаря, сохранение прогресса.

**Этап 6 — Чат-бот**
Интеграция LLM API для диалоговой практики.

**Этап 7 — Полировка**
Адаптивность, доработка дизайна, тёмная тема, деплой финальной версии, тестирование на мобильных устройствах.

## 10. Ограничения и риски

- Бесплатные тиры backend-хостингов (Render/Railway) обычно «засыпают» после периода неактивности — первый запрос после простоя может занимать 20–50 секунд. Нужно заложить в UX (лоадер с пояснением).
- Бесплатные API перевода/OCR/LLM обычно имеют лимиты запросов в день/месяц — нужно предусмотреть кэширование уже переведённых слов в БД, чтобы не дублировать запросы.
- Значение слова «на румынском» для испанских слов подразумевает, что толковый румынский словарь (DEX) — основной источник значений; для чисто испанских редких слов может не быть прямого толкования на румынском — в этом случае значение формируется через AI-перевод толкования с испанского/RAE.
